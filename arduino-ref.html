01 ¿Qué es Arduino? ▼

Arduino es una plataforma de electrónica de código abierto compuesta por dos partes inseparables: una placa con microcontrolador (el cerebro físico) y el Arduino IDE (el software donde escribís el programa). Juntas permiten que cualquier persona, sin ser ingeniero electrónico, pueda hacer que un circuito piense y reaccione al mundo real.

La idea central es sencilla: el microcontrolador puede leer entradas del mundo físico —un botón presionado, la temperatura, luz, distancia— y convertirlas en salidas —encender un LED, mover un motor, mostrar datos en pantalla. Vos escribís las reglas de ese comportamiento en el programa.

Arduino nació en 2005 en el Instituto de Diseño Interaction de Ivrea, Italia, con un objetivo claro: que estudiantes de diseño sin conocimientos de electrónica pudieran crear prototipos interactivos. Hoy es la plataforma de prototipado más popular del mundo, con millones de unidades vendidas y una comunidad enorme de proyectos y librerías gratuitas.

02 Primer programa — Blink ▼

En el mundo de la programación, cuando aprendés un lenguaje nuevo, la tradición dice que lo primero que hacés es escribir un programa que diga "Hola Mundo" en la pantalla. En el mundo de la electrónica y Arduino, nuestro "Hola Mundo" no es texto. Es algo mucho más físico: hacer parpadear una luz.

Todo programa de Arduino se llama sketch. Lo mejor de todo es que para este primer sketch no necesitás conectar nada todavía — vamos a usar el pequeño LED que ya viene integrado en la propia placa Arduino, conectado al pin 13.

ℹ️ La mayoría de placas Arduino (UNO, Nano, Mega) tienen un LED de prueba integrado conectado al Pin 13. En el código se llama LED_BUILTIN.
La anatomía de un Sketch

Abrí el Arduino IDE. Si creás un archivo nuevo (Archivo → Nuevo), vas a ver que no está vacío. Arduino siempre te da un esqueleto básico con dos funciones que siempre deben existir. Son el corazón de cualquier programa:

void setup() {
  // Se ejecuta UNA SOLA VEZ al encender o reiniciar
}

void loop() {
  // Se ejecuta INDEFINIDAMENTE, en bucle
}
¿Qué hace setup()?

Esta función se ejecuta una sola vez, justo cuando encendés el Arduino o pulsás el botón Reset. Es el momento de "preparar la mochila antes de ir al colegio": acá configurás qué pines vas a usar como entrada o salida, iniciás comunicaciones, etc. Una vez ejecutada, no se vuelve a mirar (hasta que reiniciés la placa).

¿Qué hace loop()?

Como su nombre indica (loop = bucle), el código que escribas acá se va a repetir infinitamente, una y otra vez, a la máxima velocidad posible, hasta que desconectés la corriente. Es tu rutina diaria: levantarse, comer, dormir… y vuelta a empezar. Acá va la lógica de tu proyecto: leer sensores, tomar decisiones, activar salidas.

ℹ️ Esta configuración —una función de setup y un bucle que se ejecuta continuamente— es estándar en la programación de microcontroladores. Es la única estructura que acepta el IDE estándar de Arduino.
Nuestro primer programa — Blink

Para probar el funcionamiento vamos a usar uno de los ejemplos incluidos en el IDE. Abrí Archivo → Ejemplos → 01.Basics → Blink. Vas a ver un código similar al siguiente:

Archivo → Ejemplos → 01.Basics → Blink

const int pinLED = 13;   // asignar variable led como 13

void setup() {
  pinMode(pinLED, OUTPUT); // definir pin 13 como salida
}

void loop() {
  digitalWrite(pinLED, HIGH); // encender LED
  delay(1000);               // esperar un segundo
  digitalWrite(pinLED, LOW);  // apagar LED
  delay(1000);               // esperar un segundo
}

Este ejemplo enciende y apaga un LED cada segundo. El LED empleado está integrado en muchas de las placas Arduino (UNO, MEGA, etc.) conectado físicamente al PIN 13. La función de cada línea está comentada a la derecha.

Los 3 comandos básicos

Para este primer programa usamos tres funciones esenciales que vas a usar el 90% del tiempo:

FunciónQué haceParámetros

digitalWrite(pin, estado)Cambia el estado de un pin configurado como salidapin: número · estado: HIGH (5V) o LOW (0V)

  • digitalWrite HIGH: pone 5 Voltios en el pin → enciende la corriente.
  • digitalWrite LOW: pone 0 Voltios (GND) en el pin → apaga la corriente.

Primero conectá la placa Arduino al PC mediante el cable USB. Los primeros modelos usaban un USB A-B (el mismo de las impresoras antiguas), pero otros modelos usan mini, micro o USB-C. No hace falta cable de alimentación adicional — el USB es suficiente para programar.

Con la placa y el puerto seleccionados, hacé clic en el botón → (Subir) para compilar y enviar la programación a la placa. Los LEDs TX/RX de la placa van a parpadear mientras se transfiere el programa. Tras unos segundos, la pantalla inferior del IDE debería mostrar "Subido correctamente".

08 Electrónica básica para Arduino ▼

Para conectar componentes a Arduino necesitás combinar electrónica y programación. Antes de escribir código que controle componentes reales, hay que entender tres magnitudes fundamentales y las reglas que las relacionan.

Las tres magnitudes
MagnitudSímboloUnidadQué es
Voltaje (Tensión)VVoltio [V]La energía que mueve los electrones. En Arduino trabajamos con 5V o 3.3V.
CorrienteIAmperio [A]La cantidad de electrones que fluyen por segundo. Los pines de Arduino soportan máximo 40 mA (recomendado 20 mA).
ResistenciaROhm [Ω]La oposición al paso de corriente. Se usa para proteger componentes como LEDs.
Las reglas del juego

Ley de Ohm — la relación entre las tres magnitudes:

V = I × R     // tensión = corriente × resistencia
I = V / R     // corriente = tensión / resistencia
R = V / I     // resistencia = tensión / corriente

// Ejemplo: calcular resistencia para un LED
// Vcc=5V, Vled=2V, Iled=20mA → R = (5-2) / 0.020 = 150 Ω

Leyes de Kirchhoff — en un circuito en serie, la suma de caídas de tensión es igual a la tensión de alimentación. En paralelo, la tensión en todos los ramas es la misma.

El concepto de GND

La electricidad siempre necesita un circuito cerrado: los electrones tienen que salir de la fuente de energía, hacer su trabajo y volver. Para eso existen dos puntos:

  • 5V / VCC: el punto de salida, donde hay mucha energía (presión alta).
  • GND (Ground/Tierra): el punto de retorno, el nivel cero (el desagüe).

El Arduino tiene varios pines GND repartidos por la placa. Todos son iguales y están conectados entre sí internamente. El circuito siempre debe cerrarse a GND.

El concepto de cortocircuito

Si conectás un cable directo de 5V a GND sin nada en el medio, los electrones encuentran un camino libre sin resistencia — "una autopista vacía". La placa se calienta, huele a quemado y se produce un Cortocircuito.

⚠ Siempre poné algo en el medio (una resistencia, un LED, un motor). Nunca conectes 5V directo a GND. Nunca conectes un LED sin resistencia limitadora — puede quemar el pin o el LED.
Límites del Arduino Uno
  • Corriente máxima por pin digital: 40 mA (recomendado 20 mA)
  • Corriente total de todos los pines juntos: 200 mA
  • Tensión en pines analógicos: 0 a 5V — nunca superar

08 Anatomía del Arduino Uno ▼

Entender qué hace cada parte de tu Arduino te ayuda a saber por qué las cosas funcionan (o no funcionan) cuando conectás componentes. Vamos parte por parte.

El sistema de alimentación

La placa puede recibir energía de tres formas distintas:

  • Puerto USB: permite cargar el código desde la computadora y alimenta la placa con los 5V del USB. Es lo que van a usar el 99% del tiempo al empezar.
  • Jack DC / Barril: conector negro redondo para pilas, baterías o adaptadores de corriente. El voltaje recomendado es 7V a 12V.
  • Pines Vin y GND: si la batería no tiene conector Jack, conectan los cables directamente aquí (+ a Vin, − a GND). Mismo voltaje que el Jack.
El microcontrolador

Es el chip negro y alargado que domina el centro de la placa. Normalmente un ATmega328p. Ahí es donde se guarda el código y donde se toman las decisiones. Es el cerebro de la placa.

Los Pines de Potencia

Son las tiras de agujeritos negros en los bordes, agrupados en el bloque marcado como POWER. Arduino les da energía para alimentar sensores y LEDs:

  • 5V: proporciona 5 Voltios estables.
  • 3.3V: proporciona 3.3 Voltios (para componentes más delicados como el ESP8266).
  • GND (Ground/Tierra): el negativo. Hay varios pines GND repartidos por la placa — todos son iguales y están conectados entre sí. El circuito siempre debe cerrarse a GND.
Pines digitales

Van a ver una fila larga numerada del 0 al 13. Son los pines digitales y pueden funcionar de dos formas:

  • Como SALIDA (Output): para encender o apagar cosas (0V o 5V).
  • Como ENTRADA (Input): para leer si un botón está pulsado o no.

Los pines 3, 5, 6, 9, 10 y 11 tienen un símbolo ondulado ~. Son pines PWM (Pulse Width Modulation): pueden encenderse y apagarse tan rápido que simulan voltajes intermedios. Los usamos para regular intensidad de LEDs o velocidad de motores.

Pines analógicos

Abajo a la derecha están los pines marcados como ANALOG IN (A0, A1... A5). A diferencia de los digitales (que solo entienden "Todo o Nada"), estos pines pueden medir voltajes con decimales (0.3V, 2.7V, etc.). Devuelven un valor de 0 a 1023. Son los que se usan para leer sensores analógicos: temperatura, luz, distancia, potenciómetros...

08 Cómo alimentar Arduino ▼

Arduino puede recibir energía de varias formas. Cada una tiene sus reglas. Entenderlas evita quemar la placa.

Puerto USB

Es la forma más común al empezar. El cable USB-B hace dos cosas a la vez:

  • Permite cargar el código desde la computadora.
  • Alimenta la placa con los 5V del USB (del puerto de la PC, cargador de celular o powerbank).
💡 Un powerbank USB es la opción más práctica para prototipos portátiles: 5V estables, se recarga fácil, sin necesidad de regulador.
El conector de Barril o Jack DC

Es el conector negro redondo en una esquina de la placa. Está pensado para conectar pilas, baterías o adaptadores de corriente de pared. Aquí entra en juego el Regulador de Voltaje de la placa: si meten 9V por el Jack, el regulador se encarga de "recortar" el sobrante y convertirlo en 5V estables.

  • Rango de voltaje recomendado: 7V a 12V.
  • ¿Por qué mínimo 7V? El regulador necesita un mínimo por encima de 5V para poder regular correctamente. Con 6V entraría justo y la salida sería inestable.
  • ¿Por qué máximo 12V? La diferencia entre el voltaje de entrada y 5V se disipa como calor. Con 12V y 500mA el regulador disipa (12-5)×0.5 = 3.5W — se calienta mucho. Con 9V el calor es menor.
  • Fuente típica: la pila cuadrada de 9V, o un portapilas con 6 pilas AA.
El Pin VIN

Si miran los pines de POWER, van a ver uno llamado VIN (Voltage Input). Este pin está conectado internamente al Jack DC.

  • Uso: si la batería no tiene conector Jack sino dos cables sueltos (Rojo y Negro), pueden conectarlos aquí.
  • Conexión: cable Positivo (+) va a VIN. Cable Negativo (−) va a GND.
  • Voltaje: el mismo que el Jack: 7V a 12V.
⚠ El pin VIN no tiene protección de polaridad. Si conectan el positivo y GND al revés por error, van a quemar la placa instantáneamente. Revisen los cables dos veces.
El Pin 5V

El pin 5V está pensado para ser una SALIDA (para alimentar sensores), no una entrada. Si meten energía por ahí se saltean el regulador de voltaje y las protecciones de seguridad.

  • Si la fuente da 5.5V → pueden quemar el chip.
  • Si hay un pico de tensión → adiós Arduino.
  • Si conectan el USB a la vez → conflicto eléctrico.
⚠ Por seguridad, usen el pin 5V solo para alimentar sensores, no para alimentar la placa. Solo úsenlo como entrada si tienen una fuente de 5V perfectamente regulada y regulada, nunca al mismo tiempo que el USB.

03 Variables y tipos de datos ▼

Para manejar Arduino necesitás combinar electrónica y programación. Y la programación empieza con las variables. Una variable es un pequeño espacio en la memoria del Arduino que reservamos para guardar un dato. Como si fuera una caja de mudanza.

Para que el Arduino no se lie con tanta caja, necesitamos hacer dos cosas obligatorias al crearla:

  • Ponerle una etiqueta (Nombre): para saber cómo pedirle ese dato después (velocidad, brillo, pinLed).
  • Decirle qué cabe dentro (Tipo): no es lo mismo guardar un calcetín que una enciclopedia. En programación, tenemos que definir el Tipo de Dato antes de usarlo.
Los tres tipos fundamentales

Aunque C++ tiene muchos tipos, para empezar solo necesitás dominar estos tres. Cubren el 99% de las necesidades iniciales:

El ámbito de la variable

Cuando creamos una variable, no siempre es visible para todo el código. Depende de dónde la escribamos. Esto se llama Ámbito de la variable.

Variables globales — las que declaramos fuera de cualquier función, normalmente al principio del todo del código (antes del setup):

  • Visibilidad: todo el mundo (el setup, el loop y cualquier otra función) puede verlas, leerlas y escribirlas.
  • Duración: Nunca mueren. Guardan su valor mientras el Arduino esté encendido.

Es como escribir un dato en la pizarra de la clase. Cualquiera que entre en el aula puede ver el número, borrarlo y escribir otro. El dato permanece ahí toda la clase.

Variables locales — las que declaramos dentro de una función (dentro de las llaves { }):

  • Visibilidad: solo la función donde viven puede verlas.
  • Duración: se crean al entrar a la función y se destruyen al salir.
Ejemplo práctico: El Contador vs El Temporal

Queremos contar cuántas veces parpadea un LED:

// --- VARIABLE GLOBAL ---
// Está fuera. Es la "Pizarra".
// Necesitamos que recuerde la cuenta vuelta tras vuelta.
int contadorTotal = 0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  // --- VARIABLE LOCAL ---
  // Está dentro. Es la "Libreta".
  // Se crea de nuevo en CADA vuelta del loop.
  int milisegundosEspera = 500;

  // Aumentamos la cuenta global
  contadorTotal = contadorTotal + 1;

  Serial.print("Parpadeo numero: ");
  Serial.println(contadorTotal);

  delay(milisegundosEspera);

  // Al llegar a esta llave de cierre '}', la variable
  // 'milisegundosEspera' SE DESTRUYE.
  // Pero 'contadorTotal' SOBREVIVE.
}
Consejos de nomenclatura

Arduino no admite espacios en los nombres. Convenciones:

  • int numero led = 13; ❌ Error fatal (espacio).
  • int numero_led = 13; ✅ Bien (snake_case).
  • int numeroLed = 13; ✅ Mejor (camelCase, el estándar de Arduino).

Y sean descriptivos con los nombres:

  • int x = 13; 😐 ¿Qué es x?
  • int pinLedRojo = 13; 😊 Profesional.
💡 Usá const para valores que no cambian: const int PIN_LED = 13; — el compilador optimiza y no ocupa RAM dinámica.

04 Operaciones matemáticas y lógicas ▼

Ya sabemos guardar datos en variables. Pero guardar datos sirve de poco si no hacemos nada con ellos. La potencia de un ordenador (y tu Arduino es uno pequeñito) reside en su capacidad para calcular cosas muy muy rápido.

Calcular no es solo sumar números; también es comparar cosas ("¿Es esto mayor que aquello?") y tomar decisiones lógicas ("Si pasa esto Y lo otro"). Para ello usamos los operadores. Vamos a enseñar a nuestro Arduino a sumar, restar y pensar.

La asignación (=)

En programación, el signo = se llama Operador de Asignación. Significa "meter este valor dentro de esta variable".

int numero = 5;
// Significa: Coge el valor 5 y guárdalo dentro de la caja llamada numero

El peligro de la División

Cuidado con la división. Si estás usando números enteros (int), Arduino no puede usar decimales (porque estás usando enteros, claro). En la vida real da 2.5. En Arduino, como la caja resultado es entera, corta los decimales y los tira. El resultado será 2.

int a = 5;
int b = 2;
int resultado = a / b; // ¿Cuánto da? → 2 (corta el .5)
💡 Si necesitás decimales, recordá usar variables de tipo float para todo.
float resultado = (float)a / b; → da 2.5
Los atajos ++, +=

Existen algunos "atajos" para las operaciones más comunes. Por ejemplo imaginá que querés contar vueltas. Lo normal sería: vueltas = vueltas + 1; (Coge lo que valía vueltas, súmale 1 y guardalo otra vez). En Arduino vás a ver esto escrito así:

  • vueltas++; — Suma 1 a la variable. (Incremento)
  • vueltas--; — Resta 1 a la variable. (Decremento)
  • vueltas += 5; — Suma 5 a lo que ya hubiera. (Es igual a vueltas = vueltas + 5)
ℹ️ Estos símbolos los vas a ver hasta en la sopa, especialmente en los bucles for.

Ejemplo práctico — Un contador con límite

Vamos a juntar todo en un ejemplo real. Queremos una variable que cuente del 0 al 10. Cuando llegue a 10, que vuelva a 0. Y solo imprimimos los números pares mayores que 5:

int contador = 0; // Usamos Asignación (=)

void setup() {
  Serial.begin(9600);
}

void loop() {
  // 1. Aritmética: Sumamos 1
  contador++;

  // 2. Comparación: ¿Nos hemos pasado?
  if (contador > 10) {

  }

  // 4. Lógica compuesta: Solo imprimimos si es par Y mayor que 5

  if (contador > 5 && (contador % 2 == 0)) {
    Serial.print("Numero par alto: ");
    Serial.println(contador);

}
05 Condicionales — if / else ▼

De momento, nuestros programas han sido una lista de la compra: "Haz esto, luego espera, luego haz esto otro". El Arduino obedecía en orden, línea tras línea. Pero la verdadera inteligencia surge cuando somos capaces de adaptarnos a las circunstancias.

No siempre queremos que el LED parpadee. Quizás queremos que se encienda SOLO SI pulsamos un botón, o que se apague SI hay mucha luz. Hoy vamos a aprender la estructura más fundamental de la programación: la sentencia condicional if / else (es el momento en que tu Arduino aprende a tomar decisiones).

El concepto: Un cruce de caminos

Imaginá que vas conduciendo y llegás a una bifurcación. Tenés que tomar una decisión basada en una condición:

  • SI tengo gasolina, sigo conduciendo por la autopista.
  • SI NO, me desvío a la gasolinera.

En programación, esto funciona exactamente igual. Le damos al Arduino una condición (una pregunta de Sí o No). Si la respuesta es Sí, ejecuta un bloque de código. Si es No, lo ignora (o hace otra cosa).

La sintaxis

La estructura en C++ (el lenguaje de Arduino) es bastante intuitiva:

if (condicion) {
  // Código que se ejecuta si la condición es VERDADERA
}
else {
  // Código que se ejecuta si la condición es FALSA
}
  • if: Significa "Si…".
  • (): Dentro de los paréntesis va la pregunta.
  • {}: Las llaves delimitan qué acciones ocurren.
  • else: (Opcional) Significa "Si no…". Es lo que pasa si la condición no se cumple.
Operadores de Comparación

Para que el if funcione, necesitamos hacer preguntas cuya respuesta sea Verdadero (True) o Falso (False). Para ello usamos los operadores de comparación:

OperadorSignificadoEjemplo

<=Menor o igualif (x <= 10)
>=Mayor o igualif (x >= 10)
⚠ En C++, el signo igual simple = sirve para asignar (meter un valor en una caja). Para comparar, debés usar el doble igual ==.
a = 5 → "Guarda el 5 en la variable a".
if (a == 5) → "¿Vale 'a' lo mismo que 5?"
Ejemplo práctico — El botón inteligente

Vamos a retomar el montaje clásico: un botón conectado al Pin 2 y el LED integrado en el Pin 13. Queremos que: si pulso el botón, el LED se encienda. Si no, se apague.

void setup() {
  pinMode(13, OUTPUT);
  pinMode(2, INPUT_PULLUP); // lo veremos en su momento
}

void loop() {
  // 1. Leemos el botón
  int estado = digitalRead(2);

  // 2. Tomamos la decisión
  if (estado == LOW) {
    // Si la condición es cierta (está pulsado)
    digitalWrite(13, HIGH); // Encendemos LED
  }
  else {
    // Si la condición es falsa (no está pulsado)
    digitalWrite(13, LOW);  // Apagamos LED
  }
}
💡 Al subir este código, el comportamiento es idéntico al tutorial anterior, pero el código es mucho más legible. Estamos expresando nuestra intención claramente: "Si pasa A, haz B".
¿Y si quiero que funcione al revés?

Imaginá que querés una "Luz de hombre muerto" (se apaga si pulsas, se enciende si soltás). Solo tenés que cambiar la lógica dentro de las llaves, o cambiar la pregunta:

if (estado == HIGH) { // Si el botón está SUELTO
  digitalWrite(13, HIGH);
} else {
  digitalWrite(13, LOW);
}
Anidando decisiones

¿Qué pasa si queremos condiciones más complejas? Podemos meter un if dentro de otro if. Por ejemplo: "Si pulso el botón… y además el LED estaba apagado… entonces enciéndelo" (comportamiento tipo toggle):

const int pinBoton = 2;
const int pinLed = 13;

void setup() {
  pinMode(pinLed, OUTPUT);
  pinMode(pinBoton, INPUT);
}

void loop() {
  // Primera pregunta: ¿El botón está pulsado?
  if (digitalRead(pinBoton) == HIGH) {

    // Si entramos aquí, es que el botón SÍ está pulsado.
    // Ahora hacemos la segunda pregunta (anidada):
    if (digitalRead(pinLed) == LOW) {
      // Si llegamos aquí, se cumplen las DOS condiciones:
      // 1. Botón pulsado  2. El LED estaba apagado
      digitalWrite(pinLed, HIGH); // ¡Encendemos el LED!
    }
  }

  delay(100); // Una pequeña pausa para estabilidad
}
💡 Si de momento es muy complicado, no te preocupes. Por ahora, quedate con la idea de que dentro de las llaves { ... } podés escribir cualquier código válido: encender LEDs, esperar con delay, o hacer otra pregunta if.
06 Bucles — for / while ▼

Con lo que hemos visto hasta ahora, si quisiéramos hacer parpadear un LED cinco veces, probablemente escribiríamos esto:

// encender apagar el LED
digitalWrite(13, HIGH); delay(200); digitalWrite(13, LOW); delay(200);
// encender apagar el LED
digitalWrite(13, HIGH); delay(200); digitalWrite(13, LOW); delay(200);
// ... y así hasta el cinco

Que funcionar, funciona, sí… Pero es un poco horrible. Primero, porque cansa escribirlo (y leerlo). Segundo, porque si de repente querés cambiar la velocidad, tenés que cambiarla en 20 sitios distintos. Y tercero, ¿y si querés que parpadee 1000 veces?

Precisamente una de las grandes virtudes de los ordenadores (y de Arduino) es que se les da genial repetir tareas. Para decirle a nuestra placa que repita algo muchas veces, usamos los Bucles. Hoy vamos a ver las dos herramientas fundamentales: el for y el while.

El Bucle for

El bucle for sirve cuando sabemos exactamente cuántas veces queremos repetir algo. Su estructura se compone de tres partes separadas por punto y coma:

for (inicio; condicion; actualizacion) {
  // Código a repetir
}
  • Inicio: Creamos una variable contador (normalmente llamada i) y le damos un valor inicial. Ej: int i = 0; (Empezamos en 0).
  • Condición: Preguntamos si debemos seguir repitiendo. Ej: i < 5; (¿Es i menor que 5?).
  • Actualización: Cambiamos el contador al final de cada vuelta. Ej: i++ (Suma 1 a i).
Ejemplo práctico — Contando parpadeos

En el ejemplo anterior, para parpadear un LED 5 veces, haríamos esto:

for (int i = 0; i < 5; i++) {
  digitalWrite(13, HIGH);
  delay(200);
  digitalWrite(13, LOW);
  delay(200);
}

El Arduino hará esto. Primero crea i = 0. Y luego empieza a repetir:

  • ¿0 es menor que 5? SÍ → Parpadea y suma 1 a i, es 1
  • ¿1 es menor que 5? SÍ → Parpadea y suma 1
  • ¿2 es menor que 5? SÍ → Parpadea y suma 1
  • ¿3 es menor que 5? SÍ → Parpadea y suma 1
  • ¿4 es menor que 5? SÍ → Parpadea y suma 1
  • ¿5 es menor que 5? NO. Sale del bucle y continúa con el resto del programa.
El Bucle while

A veces no sabemos cuántas veces tenemos que repetir algo. Solo sabemos que queremos hacerlo mientras se cumpla una condición. La estructura del while es más simple:

while (condicion) {
  // Código a repetir
}
⚠ En el for, la variable se actualiza sola (i++). En el while, vos sos responsable de que la condición cambie en algún momento dentro del bucle. Si la condición siempre es verdadera, el Arduino se quedará ahí atrapado sin hacer nada hasta que lo reiniciés (se "cuelga").
Ejemplo while — Esperar a un botón
// Mientras el botón NO esté pulsado... no hagas nada
while (digitalRead(2) == HIGH) {
  // Esperamos...
  delay(100);
}
// Si llegamos aquí, es que alguien ha pulsado el botón
encenderCohete();
💡 Normalmente siempre ponemos un pequeño delay porque si no, tu Arduino se pone como una moto a repetir el bucle a full velocidad. Es bueno darle un descansito.
Proyecto práctico — El coche fantástico

Para entender la potencia del for, vamos a hacer el efecto de luces más famoso de los años 80: el escáner frontal de KITT, el coche fantástico. Tenemos 5 LEDs en fila. Queremos que la luz se mueva de izquierda a derecha y vuelva, creando una estela. Sin bucles, tendríamos que escribir decenas de digitalWrite. Con bucles, lo haremos en unas pocas líneas.

Montaje: Conectá 5 LEDs (con sus resistencias) a los pines digitales consecutivos: 2, 3, 4, 5 y 6. Alinealos en la protoboard.

void setup() {
  // Configurar pines del 2 al 6 como SALIDA
  // En vez de escribir 5 líneas pinMode, usamos un bucle
  for (int i = 2; i <= 6; i++) {
    pinMode(i, OUTPUT);
  }
}

void loop() {
  // --- IDA: De izquierda a derecha (Pines 2 al 6) ---
  for (int i = 2; i <= 6; i++) {
    digitalWrite(i, HIGH); // Encendemos el LED actual
    delay(100);             // Esperamos un poquito
    digitalWrite(i, LOW);  // Apagamos (para dar efecto de movimiento)
  }

  // --- VUELTA: De derecha a izquierda (Pines 5 al 3) ---
  // Nota: No empezamos en el 6 ni acabamos en el 2 para no repetir los extremos
  for (int i = 5; i >= 3; i--) {
    digitalWrite(i, HIGH);
    delay(100);
    digitalWrite(i, LOW);
  }
}
💡 Si querés que la estela sea más larga (que queden un poco encendidos los anteriores), podés jugar con los tiempos o no apagar el LED inmediatamente. Para empezar, este efecto "punto que se mueve" es perfecto.
07 Funciones y librerías ▼

A medida que los proyectos crecen, el loop() empieza a hacerse eterno: cada vez más largo, más difícil de leer y con mucho código repetido. Las funciones son la solución.

Una función es como una receta de cocina. La escribís una vez, le ponés un nombre y después la llamás cuando la necesitás. setup(), loop(), digitalWrite(), delay() — todas son funciones. Las primeras dos las escribe Arduino automáticamente; el resto las llamamos nosotros.

Creando tu primera función

La estructura básica para definir una función es:

tipoDevuelto nombreFuncion(parametros) {
  // El código de la receta
}

Un ejemplo sencillo: una función llamada parpadearTresVeces():

void setup() {
  pinMode(13, OUTPUT);
}

void loop() {
  // En lugar de escribir todo el código aquí, solo llamamos a la función
  parpadearTresVeces();

  delay(2000); // Esperamos un poco

  parpadearTresVeces(); // ¡Podemos reutilizarla las veces que queramos!
}

// --- ZONA DE TUS FUNCIONES ---
// (Normalmente se escriben después del loop)

void parpadearTresVeces() {
  for(int i=0; i<3; i++) {
    digitalWrite(13, HIGH);
    delay(200);
    digitalWrite(13, LOW);
    delay(200);
  }
}
  • void: significa "vacío". Esta función hace cosas (enciende luces) pero no nos devuelve ningún resultado (no nos da un número).
  • parpadearTresVeces: el nombre que le pusimos.
  • (): paréntesis vacíos, porque no necesita información extra para funcionar.
  • { ... }: el cuerpo de la función.
💡 Gracias a esto, el loop() queda limpísimo y es muy fácil de leer. Cualquiera que lea parpadearTresVeces() entiende qué pasa sin necesidad de ver los digitalWrite internos.
Funciones con parámetros

La función anterior está bien, pero es un poco rígida. Siempre parpadea 3 veces. ¿Y si queremos que parpadee 5? ¿O 10? Podemos pasarle información a la función a través de los paréntesis. Esto se llama Parámetros de la función:

void parpadear(int numeroVeces) {
  for(int i=0; i < numeroVeces; i++) {
    digitalWrite(13, HIGH);
    delay(200);
    digitalWrite(13, LOW);
    delay(200);
  }
}

void loop() {
  parpadear(5);  // Parpadea 5 veces
  delay(1000);
  parpadear(2);  // Parpadea 2 veces
}

Creamos una herramienta genérica que se adapta a lo que necesitemos.

Las librerías: usando el código de otros

Una librería no es más que un conjunto de funciones que podemos añadir a nuestro proyecto para no tener que reinventar la rueda. Gente muy lista ha dedicado su tiempo a escribir cientos de funciones súper útiles para controlar motores, pantallas, sensores complejos o conectarse a Internet. Eso es una Librería.

Cómo se usan — para usar una librería, primero tenemos que avisar a nuestro programa que la queremos incluir. Esto se hace con el comando #include:

#include <Servo.h> // Incluimos la "caja de herramientas" del Servo

Servo miMotor; // Creamos nuestro objeto motor

void setup() {
  miMotor.attach(9); // Le decimos que el motor está en el pin 9
}

void loop() {
  // ¡Mirá qué fácil! No tenemos que saber cómo funcionan los pulsos eléctricos.
  // Solo usamos la función "write" que viene en la librería.
  miMotor.write(90);  // Ponete a 90 grados
  delay(1000);
  miMotor.write(0);   // Ponete a 0 grados
  delay(1000);
}

Sin la librería, tendríamos que haber escrito decenas de líneas de código complejo con digitalWrite y microsegundos para mover ese motor. Con la librería, es una sola línea.

¿Dónde consigo librerías? — Arduino tiene un Gestor de Librerías integrado:

  1. Ir a Sketch → Include Library → Manage Libraries...
  2. Buscar lo que necesitan (ej: "DHT11" para temperatura, "NeoPixel" para luces de colores).
  3. Le dan a Install.
💡 Antes de pelearse programando un sensor complejo desde cero, busquen en Google "Arduino library [nombre del sensor]". El 99% de las veces, alguien ya ha hecho el trabajo duro.

08 Entradas digitales ▼

Una señal digital solo puede tener dos valores: LOW (0V) o HIGH (5V). El proceso de discretización toma la tensión del pin y la convierte a uno de esos dos estados usando un umbral: de 0 a 2,5V el Arduino lee LOW, de 2,5V a 5V lee HIGH. Nunca hay que superar el rango 0–5V o se daña el microcontrolador.

Cuando un sensor o dispositivo externo conecta el pin a 5V o a GND, el Arduino lee directamente con digitalRead(pin). La función devuelve HIGH o LOW y el pin trabaja en alta impedancia (~100 MΩ), lo que significa que prácticamente no consume corriente del sensor.

Conexión típica sensor → pin digital

Sensor conectado a pin digital: el sensor entrega 5V o GND al pin, Arduino lee HIGH o LOW.

Código básico — entrada digital
const int sensorPin = 4;
int sensorValue;

void setup() {
  pinMode(sensorPin, INPUT);
  Serial.begin(9600);
}

void loop() {
  sensorValue = digitalRead(sensorPin); // devuelve HIGH o LOW
  Serial.println(sensorValue);
  delay(500);
}
Lectura de señales mayores a 5V — divisor de tensión

Si la señal del sensor supera los 5V, no se puede conectar directo al pin. Se usa un divisor de tensión con R1 = 10 kΩ y R2 = 4,7 kΩ para reducir la tensión a un rango seguro (0–3,9V), que el Arduino puede interpretar sin problemas.

Divisor de tensión R1=10K / R2=4K7: reduce señales mayores a 5V a un rango seguro para el pin digital.

08 Salidas digitales ▼

Una salida digital puede entregar solo dos tensiones: 0V (LOW) o 5V (HIGH). Todos los pines digitales son configurables como entrada o salida. El UNO y el Nano tienen 22 pines digitales, el Mini 20, y el Mega 70. Con pinMode(pin, OUTPUT) y digitalWrite(pin, HIGH/LOW) controlamos cualquier carga conectada.

El límite de corriente es crítico: máximo 40 mA por pin (se recomienda no superar 20 mA), y la suma total de todos los pines no debe exceder 300 mA. Para cargas que consumen más (motores, tiras LED, relés) se necesita un transistor BJT o MOSFET que actúe como interruptor: el pin Arduino da la orden, el transistor maneja la corriente real. Siempre usar resistencia ≥ 300 Ω en serie con LEDs.

Esquema de medición — salida digital con voltímetro

Medición de la salida digital con voltímetro: muestra 5V (HIGH) o 0V (LOW) según el estado del pin.

    if (c == '1') digitalWrite(ledPin, HIGH); // enciende
    if (c == '0') digitalWrite(ledPin, LOW);  // apaga
  }
}

08 Entradas analógicas ▼

A diferencia de las entradas digitales, una señal analógica puede tomar cualquier valor entre 0V y 5V. El ADC (Conversor Analógico-Digital) del Arduino convierte esa tensión a un número entero. En el UNO es de 10 bits: divide el rango en 1024 niveles y devuelve un valor de 0 a 1023. La precisión es ±2,44 mV por paso (5V ÷ 1024 / 2).

La función analogRead(pin) no necesita pinMode() previo — los pines A0–A5 son exclusivamente de entrada analógica. La frecuencia de muestreo máxima es ~9.600 Hz. Para convertir el valor leído a voltaje real: V = lectura × (5.0 / 1023.0).

Conexión típica sensor → pin analógico

Sensor conectado a pin analógico: entrega una tensión variable entre 0V y 5V que el ADC convierte a 0–1023.

Código básico — lectura analógica
const int sensorPin = A0;
int sensorValue;
float voltage;

void setup() {
  Serial.begin(9600);
}

void loop() {
  sensorValue = analogRead(sensorPin);       // 0–1023
  voltage = sensorValue * (5.0 / 1023.0);   // convertir a voltaje
  Serial.print("Valor: "); Serial.print(sensorValue);
  Serial.print("  Voltaje: "); Serial.println(voltage);
  delay(500);
}

08 Salidas analógicas — PWM ▼

Arduino no genera señal analógica real. Lo que sí puede hacer es simularla con PWM (Modulación por Ancho de Pulso): en lugar de entregar un voltaje constante de 2,5V, el pin pulsa entre 5V y 0V a alta frecuencia. Si está el 50% del tiempo en HIGH, el voltaje promedio que percibe la carga es 2,5V. El parámetro que se controla se llama duty cycle (ciclo de trabajo), que es el porcentaje de tiempo que el pin está en HIGH.

Importante: el PWM no es una señal analógica. Durante el tiempo que está encendido, el pin sigue entregando los 5V completos de Vcc. Esto puede dañar dispositivos que no son compatibles con esa tensión. El voltaje promedio se calcula como: V_medio = Vcc × DutyCycle / 100. Es útil para controlar brillo de LEDs y velocidad de motores DC, pero no para alimentar circuitos que necesitan una tensión analógica estable.

Gráfica de duty cycles — 10%, 30%, 50%, 90%

Distintos duty cycles: a mayor % de tiempo en HIGH, mayor voltaje promedio. 0% = 0V, 50% = 2,5V, 100% = 5V.

Código básico — analogWrite()
const int ledPin = 9; // pin PWM (marcado con ~ en la placa)

void setup() {
  pinMode(ledPin, OUTPUT);
}

void loop() {
  analogWrite(ledPin, 0);   // 0% duty → 0V
  delay(1000);
  analogWrite(ledPin, 128); // 50% duty → ~2.5V
  delay(1000);
  analogWrite(ledPin, 255); // 100% duty → 5V
  delay(1000);
}

08 Interrupciones ▼

La forma habitual de detectar un evento es el polling: preguntar repetidamente en el loop() si algo cambió. El problema es que si el loop() está ocupado con un delay() o cualquier otra tarea, puede perderse un evento corto. Además consume CPU constantemente aunque no pase nada.

La solución es una interrupción: se registra una función especial (ISR) y cuando ocurre el evento en el pin, el hardware pausa el programa al instante, ejecuta la ISR, y luego retoma exactamente donde estaba. No importa qué esté haciendo el loop() — la interrupción salta igual.

08 Encender un LED con Arduino ▼

Un LED (Light Emitting Diode) es un diodo que emite luz al ser atravesado por corriente eléctrica. Tiene polaridad: solo conduce en un sentido. La pata larga es el ánodo (+) y la corta el cátodo (–).

El LED no tiene resistencia interna significativa: una vez que supera su tensión de polarización (Vf), la corriente crece sin límite y lo destruye. Por eso siempre necesitás una resistencia en serie. La resistencia absorbe la diferencia de tensión: V_R = Vcc – Vf. Con la Ley de Ohm: R = (Vcc – Vf) / I.

19 Leer un pulsador con Arduino ▼

Para leer un pulsador, Arduino necesita que el pin tenga siempre una tensión de referencia definida. Sin ella el pin queda en estado de alta impedancia (pin flotante): cuando el pulsador está abierto el pin no está conectado a nada y capta interferencias electromagnéticas del ambiente, dando lecturas aleatorias e impredecibles.

Problema 1 — Conexión directa: pin flotante

Izquierda: pulsador a GND — cuando está abierto el pin no tiene referencia → flotante. Derecha: pulsador a 5V — mismo problema.

Problema 2 — Doble conexión: cortocircuito

Para evitar el pin flotante podría parecer lógico conectar el pin a 5V y también a GND a través del pulsador. Pero al cerrar el pulsador se genera un cortocircuito directo entre 5V y GND — corriente ilimitada, destrucción de componentes.

Al cerrar el pulsador, 5V y GND quedan directamente conectados → cortocircuito. Nunca hacer esto.

Solución correcta — Resistencia Pull-Up o Pull-Down

La solución es agregar una resistencia de referencia que mantenga el pin en un estado definido cuando el pulsador está abierto, pero que limite la corriente cuando está cerrado:

  • Pull-Up: R desde 5V al pin → fuerza HIGH cuando abierto. Al pulsar: LOW
  • Pull-Down: R desde GND al pin → fuerza LOW cuando abierto. Al pulsar: HIGH

Izquierda: resistencia pull-up (HIGH en reposo, LOW al pulsar). Derecha: resistencia pull-down (LOW en reposo, HIGH al pulsar).

Montaje real — Pull-Up y Pull-Down

Montaje en protoboard de ambas configuraciones. Valores típicos de resistencia: 1kΩ a 10kΩ.

Código — Lectura con resistencia externa (INPUT)
const int inputPin = 2;
int value = 0;

void setup() {
  Serial.begin(9600);
  pinMode(inputPin, INPUT); // resistencia externa obligatoria
}

void loop() {
  value = digitalRead(inputPin);
  if (value == HIGH) {
    Serial.println("Encendido");
  } else {
    Serial.println("Apagado");
  }
  delay(1000);
}
Atajo — Pull-up interno del Arduino (INPUT_PULLUP)

Arduino tiene resistencias pull-up internas de ~30kΩ activables por software. Con INPUT_PULLUP no necesitás resistencia externa, pero la lógica queda invertida: HIGH = suelto, LOW = pulsado.

pinMode(inputPin, INPUT_PULLUP); // sin resistencia externa
// LOW = pulsado (lógica invertida)
if (digitalRead(inputPin) == LOW) {
  // pulsador presionado
}
¿Qué valor de resistencia elegir?
  • Muy pequeña: mucha autoridad pero mayor consumo de corriente al pulsar
  • Muy grande: poco consumo pero más susceptible a ruido e interferencias
  • Valores típicos: 1kΩ a 10kΩ — buen equilibrio entre autoridad y consumo
⚠ Las pull-up internas del Arduino (~30kΩ) tienen poca "autoridad" — si hay mucho ruido en el circuito, pueden dar lecturas incorrectas. Para entornos ruidosos usá resistencia externa de 1kΩ a 4.7kΩ.
08 Leer una resistencia variable — LDR / NTC ▼

Una resistencia variable cambia su valor óhmico según una magnitud física: la LDR (fotorresistencia) disminuye su resistencia al aumentar la luz, la NTC (termistor) disminuye con el aumento de temperatura. El problema es que Arduino no mide resistencia — solo tensión.

La solución es un divisor de tensión: la resistencia variable en serie con una resistencia fija (10kΩ). Arduino mide el punto medio. Cuando R_variable cambia, la tensión en el punto medio cambia proporcionalmente y podés inferir la magnitud física.

Esquema eléctrico — Divisor de tensión: Rsensor + Rc → A0

Divisor de tensión: Rsensor (arriba) en serie con Rc de calibración (abajo). El punto medio se conecta a A0. Al variar Rsensor, cambia la tensión en A0.

Montaje en protoboard

Montaje real: 5V → Rsensor → nodo A0 → Rc → GND.

Código — Calcular el valor de la resistencia

Leemos la tensión en A0 y usamos la ecuación del divisor de tensión despejada para calcular Rsensor. Se usa aritmética de enteros (sin float) para ahorrar memoria y velocidad.

const int sensorPin = A0;
const int Rc = 1500; // resistencia de calibración en Ω

int  V;        // lectura ADC 0–1023
long Rsensor;  // resistencia calculada en Ω

void setup() { }

void loop() {
  V = analogRead(sensorPin);           // leer ADC
  Rsensor = 1024L * Rc / V - Rc;      // calcular Rsensor
  // acá usás Rsensor: encender LED, imprimir, etc.
  delay(1000);
}
¿Qué valor de Rc usar?
  • Suficientemente grande para limitar la corriente cuando Rsensor llega a 0Ω
  • Suficientemente pequeña para no perder precisión de medición
  • Regla práctica: Rc igual al valor de Rsensor a media escala del sensor
  • Valores típicos: 1kΩ a 4.7kΩ para LDR y NTC comunes
💡 Siempre que sea posible, usá aritmética de enteros en lugar de float. Las operaciones en punto flotante ocupan más memoria y son significativamente más lentas en el AVR.
19 Leer un potenciómetro con Arduino ▼

Un potenciómetro es un divisor de tensión ajustable manualmente. Internamente tiene una pista resistiva con un contacto móvil (cursor/wiper) que se desplaza por ella. Tiene tres terminales: dos extremos fijos y uno variable (el cursor). Al conectar los extremos a 5V y GND, el cursor entrega cualquier tensión entre 0V y 5V según la posición.

Valores comunes de Rmax: 5kΩ, 10kΩ, 20kΩ. El potenciómetro ya es el divisor de tensión — no necesita resistencia fija adicional. El cursor es el punto medio del divisor interno.

Tipos de potenciómetro

Tipos de geometría: lineal (deslizante) y rotativo (el más común en electrónica).

Curva de respuesta — Lineal vs Logarítmico

Lineal: resistencia proporcional al desplazamiento. Logarítmico: mayor resolución en valores bajos (audío, volumen). Pseudo-log: intermedio.

Esquema eléctrico — 3 terminales → Arduino

Terminal 1 → 5V · Terminal 2 (cursor) → A0 · Terminal 3 → GND. Sin resistencia adicional.

Montaje en protoboard

Montaje real: 5V (rojo) y GND (negro) a los extremos, cursor (verde) a la entrada analógica.

08 Debounce — Eliminar rebotes del pulsador ▼

Los contactos mecánicos de un pulsador no se cierran limpiamente: rebotan durante 10–50 ms generando múltiples señales HIGH/LOW antes de estabilizarse. Para el Arduino, una sola presión parece 5, 10 o 20 pulsaciones. Si estás contando clicks o haciendo toggle, el rebote genera comportamientos erráticos imposibles de debuggear sin saber que existen.

El debounce (antirrebote) consiste en ignorar los cambios de estado que ocurren demasiado rápido. La técnica correcta usa millis(): guardamos el momento del último cambio y solo aceptamos uno nuevo si pasaron más de 50 ms. Esto no bloquea el loop() — a diferencia del debounce con delay().

Señal digital limpia — sin rebote (osciloscopio)

Señal de una salida digital de Arduino al cambiar de HIGH a LOW: flanco perfectamente limpio, sin ruido.

Señal de un pulsador real con rebote (osciloscopio)

La misma transición generada por un pulsador mecánico: decenas de picos de ruido en los primeros microsegundos — cada pico puede disparar una interrupción.

Esquema — Circuito de prueba del rebote

Circuito de prueba: pin 2 con Pull-UP interno y un cable a GND (o pulsador). Al conectar, se disparan múltiples interrupciones por el rebote.

Debounce por hardware — condensador 1µF

Debounce por hardware: condensador de 1µF en paralelo con el pulsador filtra el ruido. Es más robusto pero agrega componentes al circuito.

Código — Debounce con millis() (no bloqueante)
const int   PIN_BTN   = 2;
const int   PIN_LED   = 13;
const long  DEBOUNCE  = 50;

int           estadoBtn      = HIGH;
int           estadoAnterior = HIGH;
bool          ledOn          = false;
unsigned long tUltimoCambio  = 0;

void setup() {
  pinMode(PIN_BTN, INPUT_PULLUP);
  pinMode(PIN_LED, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  int lectura = digitalRead(PIN_BTN);

  if (lectura != estadoAnterior)
    tUltimoCambio = millis(); // registra el cambio

  if ((millis() - tUltimoCambio) > DEBOUNCE) {
    // lleva >50ms estable → cambio real
    if (lectura != estadoBtn) {
      estadoBtn = lectura;
      if (estadoBtn == LOW) {       // flanco bajada = pulsación
        ledOn = !ledOn;
        digitalWrite(PIN_LED, ledOn);
        Serial.println("Click!");
      }
    }
  }
  estadoAnterior = lectura;
}

  if (millis() - tISR > 50) {
    pulsado = true;

  }
}

19 EEPROM — Guardar datos entre reinicios ▼

Cuando el Arduino se apaga o reinicia, toda la RAM se borra. La EEPROM es una memoria no volátil integrada en el chip que mantiene los datos sin energía, igual que un pendrive. El Arduino Uno tiene 1 KB (1024 bytes). Es ideal para guardar configuraciones, calibraciones, contadores de uso o el último estado del sistema.

La limitación crítica: la EEPROM tiene una vida útil de unas 100.000 escrituras por dirección. Nunca la escribas dentro de un loop() sin control — en pocos minutos la destruirías. Usá EEPROM.update() o EEPROM.put() que solo escriben si el valor cambió realmente.

08 Bus I2C — Conectar múltiples dispositivos con 2 cables ▼

El bus I2C (Inter-Integrated Circuit, también llamado TWI) es un protocolo que usa solo 2 cables: SDA (datos) y SCL (reloj). Fue desarrollado por Philips en 1982 y se convirtió en estándar: acelerómetros, brújulas, displays OLED, sensores de temperatura — la mayoría de sensores modernos tienen I2C.

Arquitectura del bus I2C: un maestro (Arduino) y múltiples esclavos en el mismo par de cables SDA/SCL, con resistencias Pull-UP a Vcc.

Cada dispositivo tiene una dirección única de 7 bits (hasta 112 dispositivos en el mismo bus). La velocidad estándar es 100 kHz, con modo rápido de 400 kHz. Las resistencias Pull-UP internas del Arduino (20–30 kΩ) son suficientes para velocidades bajas; para mayor velocidad o distancia usá resistencias externas de 1k–4k7.

void setup() {
  Wire.begin();
  Serial.begin(9600);
  Serial.println("Escaneando bus I2C...");

  for (byte addr = 8; addr < 120; addr++) {
    Wire.beginTransmission(addr);
    byte rc = Wire.endTransmission();
    if (rc == 0) {
      Serial.print("Encontrado en 0x");
      Serial.println(addr, HEX);
    }
  }
  Serial.println("Terminado");
}

19 Bus SPI — Comunicación rápida Full Duplex ▼

El bus SPI (Serial Peripheral Interface) es un protocolo síncrono Full Duplex: el maestro puede enviar y recibir simultáneamente. Usa 4 líneas: MOSI (maestro→esclavo), MISO (esclavo→maestro), SCK (reloj) y SS/CS (selección de esclavo). Es más rápido que I2C pero requiere más cables.

Conexión básica SPI entre maestro y un esclavo: 4 líneas (SCK, MOSI, MISO, SS).

Con múltiples esclavos: SCK, MOSI y MISO se comparten, pero cada esclavo necesita su propia línea SS.

Alternativa en cascada: se usa una sola línea SS pero los datos atraviesan todos los esclavos en cadena.

PlacaSSMOSIMISOSCK
Uno / Nano10111213
Mega53515052
Funciones principales — librería SPI.h
#include <SPI.h>

SPI.begin();
SPI.beginTransaction(SPISettings(2000000, MSBFIRST, SPI_MODE0));
                                    // 2 MHz, MSB primero, modo 0
byte resp = SPI.transfer(dato);   // envía y recibe 1 byte simultáneamente
SPI.endTransaction();

// Modos de reloj disponibles:
// SPI_MODE0: CLK idle LOW, muestreo en flanco subida
// SPI_MODE1: CLK idle LOW, muestreo en flanco bajada
// SPI_MODE2: CLK idle HIGH, muestreo en flanco bajada
// SPI_MODE3: CLK idle HIGH, muestreo en flanco subida
💡 En la práctica casi nunca usás las funciones SPI directamente: las librerías de cada componente (tarjeta SD, pantallas TFT, etc.) se encargan del protocolo. Lo importante es saber qué pines usa SPI para no tener conflictos con otros dispositivos conectados.

const int pinLED = 13;

void setup() {
  Serial.begin(9600);
  pinMode(pinLED, OUTPUT);
}

void loop() {
  if (Serial.available() > 0) {
    char option = Serial.read();
    if (option >= '1' && option <= '9') {
      option -= '0';
      for (int i = 0; i < option; i++) {
        digitalWrite(pinLED, HIGH); delay(100);
        digitalWrite(pinLED, LOW);  delay(200);
      }
    }
  }
}
💡 La función write() de PySerial envía bytes, no texto. Siempre precedé el string con b (ej: b'9') o usá encode(). El sleep(2) es necesario porque Arduino hace reset al abrir el puerto — si enviás datos antes de que termine el reset, los pierde.
